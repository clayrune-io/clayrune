## 2. Chat stream and catch-up (`static/js/resume-preview.js`, read fully)

### FE1 · HIGH · L — the catch-up path drops repeated lines and then shows the wrong ones (measured)
`resume-preview.js:612-636`. `_readAgentBuffer` walks the lines the client
missed with `for (const text of missing)` and finds each line's position with
`missing.indexOf(text)` (`:615`). `indexOf` returns the FIRST line with that
text, so for the second and later copies of any repeated line `_mi` points
back at the first copy. The race guard on `:618`
(`agentServerLines >= have + _mi + 1`) is then true, and the line is skipped:
not pushed to `agentOutputBuffers`, not drawn, cursor not advanced. The cursor
ends short by the number of skipped lines, so the next catch-up (or the gap
branch of `_claimAgentOutputEvent`, `:820`) slices the server buffer from too
early an index and appends the last few server lines a second time. The
timestamp read on `:622` and `:635` (`missingTs[_mi]`) is wrong for the same
reason.

**Failure:** a phone loses its stream for a minute (the case the function's
own comment names, `:513-519`); the agent prints two identical tool lines or
two identical short lines in that minute; on catch-up the chat is missing a
line in the middle and has a repeated line at the end, and stays that way
until something forces a full repaint from the server.

**Measured** in the live page, `GET` only, on three idle sessions of the
reviewed install: the client buffer and cursor were set K lines behind the
server, exactly as a dropped stream leaves them, and
`window._reconcileAgentBuffer` was called twice.

| Server lines | Client behind by | Repeated lines in the missed slice | After 1st catch-up | After 2nd | First index that differs from the server |
|---|---|---|---|---|---|
| 215 | 20 | 0 | 215 lines | 215 | none (correct) |
| 215 | 100 | 11 | 209 | 215 | 140 |
| 354 | 100 | 4 | 350 | 354 | 265 |
| 77 | 20 | 2 | 75 | 77 | 64 |
| 77 | 77 | 18 | 59 | 75 | 5 |

Every run with a repeated line in the slice ended with a buffer that differs
from the server's; every run without one was correct.

**Smallest fix:** iterate by index (`for (let i = 0; i < missing.length; i++)`),
use `i` where `_mi` is used. **Smoke:** `agent-log-epoch-reconcile.mjs` calls
this function but through the shrink/epoch branch (`:597-610`); nothing feeds
the append branch a repeated line, so no smoke catches it.

### FE5 · HIGH · E/L — one stream per running session whether or not anyone is looking, with no ceiling
`conversation.js:6269-6278`: `wantsLiveStream` is true for every session whose
status is `running`, and `connectAgentStream` is called for it. The loop that
calls this (`index.html:3918`, 15 s) runs for every project with a running
agent, modal open or not. The comment on `:6257-6258` says idle background
sessions are skipped "to preserve Chromium's 6-slot per-origin cap"; running
background sessions are not. `connectAgentStream` (`resume-preview.js:825-846`)
has no count check. The only limiter is for popped-out windows (`:832`).

**Measured:** with no modal open, the idle dashboard held two agent
`EventSource` connections, one per running session (section 1).
**Read, not measured:** at six sessions running at once across all projects
(one hivemind with three workers plus an orchestrator plus two ordinary
agents is enough) the tab holds six streams. On a plain `http://localhost`
origin Chromium allows six connections, so every later `fetch` from that tab
queues behind streams that do not end until a turn completes: the grid stops
refreshing, Send and Stop do not leave the browser. A second dashboard tab
shares the same six. Over the tunnel (HTTP/2) the cap does not apply, which
is why it shows on the host first.

**What is sound here:** the stream is closed on `turn_complete`
(`resume-preview.js:1127-1130`), on a terminal `status` (`:1189-1192`), on
`error` (`:1239-1242`) and on tab close (`:238-242`), each time with its
watchdog interval; reconnect is limited to `running`/`idle` (`:860`,
`:1289`) and to three tries (`:1299`). The lifecycle of one stream is right.
The count is the defect.

**Smallest fix:** connect a background running session only while its chat is
on screen (the `isActiveTab` test already computed on `:6265`), and let the
15 s status poll carry status for the rest, as it already does for idle ones;
or cap the registry at four and drop the least recently viewed. **Smoke:**
none counts open streams.

## 3. Text placed inside a JavaScript string in an inline handler

The pattern is `onclick="fn('${esc(x)}')"`. Counted by script over
`static/js/*.js` and `static/index.html`: **880** template values sit inside a
single-quoted string in an inline `on…=` attribute, 164 distinct expressions.
About 700 of them carry an id the server generated. The rest carry names,
titles, paths and labels.

Two facts make every one of the second kind a defect:

1. `esc()` (`index.html:2806-2810`) escapes `& < > "` and not `'`.
2. Escaping `'` as `&#39;` would not help: the browser decodes the attribute
   before it parses the handler, so the entity is a quote again by the time
   the JavaScript runs. A value inside a JS string inside an attribute has to
   be JS-escaped first and HTML-escaped second. Three helpers in the codebase
   already do that or half of it: `jsAttr` (`agent-log.js:484`), `_jsAttr`
   (`documents-search.js:38-40`), and `_wfJsStrEsc`
   (`workflow-builder.js:149-151`, JS half only). The other call sites use
   `esc()`.

**Measured** in the live page with the page's own `esc()`: the value
`x');hit();//` comes out of `esc()` unchanged; placed in the template from
`floor.js:302` and parsed back from the DOM, the handler source is
`event.stopPropagation();floorRename('abc123','x');hit();//')`, and running it
with stubs calls `hit` once. The value `Sam's helper` gives
`SyntaxError: missing ) after argument list`, so the click does nothing.

### FE2 · HIGH · M (security) — an agent's self-chosen Floor name runs as script when the name is clicked
Sink: `floor.js:302`,
`onclick="…floorRename('${esc(f.session_id)}','${esc(f.name || '')}')"`.
Source: `POST /api/floor/figure/<id>/name`. The route is the one every agent is
told to call to name itself (`floor_routes.py:454-478`), and the only cleaning
is whitespace collapse and a length cut (`_clean_name`,
`floor_routes.py:96-97`). So the text is agent-controlled, and an agent that
has read a hostile page or file is controlled by that page.

**Failure:** an agent sets its name to `x');<script>//`. The Floor shows the
name; clicking it (the rename affordance) runs the script in the dashboard
origin. That script can do everything the human can do in the UI, including
the steps the product keeps human-only: approve a plan, promote a skill,
create a secret, hire a character. The agent could already run commands; what
it gains is the human's side of every gate. The ordinary failure is smaller
and certain: any name with an apostrophe cannot be renamed by clicking it.

**Smallest fix:** `data-name="${esc(f.name)}"` and read
`this.dataset.name` in the handler; or `_jsAttr`. **Smoke:** none
(`hivemind-roster.mjs` references the Floor functions, not this path).

`onclick="openHmRunsModal(…,'${esc(ws.title || ws.id)}')"`. Source: the

**Smallest fix for the class:** one shared `jsAttr()` next to `esc()` in
`index.html`, and replace `'${esc(` with it inside handlers for any value that
is not a generated id. Longer term, `data-*` attributes and one delegated
listener per panel remove the class.

### FE12 · LOW · M — about 118 private copies of the HTML-escape helper, in three variants
