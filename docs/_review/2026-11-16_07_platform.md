### 1. Vault: `mc/secrets_store.py`, `secrets_routes.py`, exec-stream, restart handover

#### 1a. `mc/secrets_store.py` (read fully, 2874 lines)

**P1 — `mc/secrets_store.py:2567-2569`, `:2009-2015`, `mc/core.py:132` — E — medium.
Every secret read rewrites the whole store and spawns two `icacls` processes, under the vault lock.**
`get_secret_value` bumps `last_used_at`/`use_count` and calls `_save_store`
on every dispense. `_save_store` → `_write_private_bytes` hardens the temp
file and the final file, and on Windows each `_harden_secret_perms` is one
`icacls` subprocess. All of it runs inside `with _lock:`, so every other
vault read and the audit append wait behind it. **Measured** (scratch
`CLAYRUNE_HOME`, file backend, 30 entries, Windows): 35 ms per read, 2
`subprocess.run` per read, 2 store loads per read. A command with five
placeholders is five full store rewrites and ten `icacls` spawns
(`resolve_placeholders`, `:2693-2700`). A store that cannot be written (disk
full, ACL damage) also fails the read, although the decrypt already succeeded.
Smallest fix: harden only when the file is created (the ACL survives
`os.replace` of a file that was hardened as a temp only if the temp is
hardened, so harden the temp once and drop the second call), and move the
usage counters to a sidecar or batch them so a read is not a store rewrite.
Tests: none measure it; `tests/test_secrets_store.py` asserts the counter
value only.

**P2 — `mc/secrets_store.py:2203`, `:2217-2218`, `:1982`, `:785` — E — low.
`list_secrets(check_readable=True)` re-reads and re-parses the store 2N+1 times.**
Each entry calls `is_readable` (one `_load_store`), which calls `_open` →
`load_master_key` (a second `_load_store` in non-passphrase mode, plus one OS
keyring read, one trial decrypt and, on Windows, two DPAPI unseals in
`_maintain_key_mirror` `:620`, `:632`). **Measured**: 61 `_load_store` calls
for 30 entries (14 ms on the file backend; the keyring and DPAPI legs are
read, not measured). Smallest fix: load the store and the key once in
`list_secrets` and trial-decrypt each record against them. No test counts
loads.

**P3 — `mc/secrets_store.py:2814-2816` with `:2179-2180` — M — medium.
A backup entry with a non-numeric `digits`/`period` makes the whole vault list unreadable.**
`_import_entry_raw` copies `issuer/account/digits/period/algorithm` from the
archive with no type check, and `kind`/`scope` likewise (`:2808`, `:2812`).
`_public` then does `int(rec.get('digits', 6) or 6)` for every record.
**Measured**: `_public('x', {'digits': 'abc'})` raises `ValueError`, and
`list_secrets` has no per-record guard, so one such record fails
`GET /api/secrets` for every entry until the store is hand-edited. The same
function reads `entry['value']` (`:2801`) and `entry['name']` (`:2787`)
unguarded inside the import loop at `:2870-2872`: entry k raising `KeyError`
leaves entries 1..k-1 already saved and the caller with an exception, not a
result (half-imported, no `import` audit line). The archive is
passphrase-sealed, so this needs a damaged or hand-built archive, not a
random one. Smallest fix: validate every entry (types, `kind` in the two
known values, `digits`/`period` ints) before the first write, in
`import_all_from_backup`. Existing tests round-trip well-formed exports only.

**P4 — `mc/secrets_store.py:2402`, `:280`, `:266-279` — L — medium.
Three different answers to "which port is the server on".**
`server.py:683` binds `MC_PORT`, else `config.json` `port`, else 5199.
`exec_route_port()` returns `MC_PORT` else 5199 and its docstring says both
that it mirrors the config lookup and that it deliberately does not.
`_TRIGGER_TYPE_URL` is the literal `127.0.0.1:5199`. Agent children get
`CLAYRUNE_PORT`, not `MC_PORT` (`mc/agent_spawn.py:109-111`), so a server
started as `python server.py` with only `config.json` `port` set to anything
but 5199 gets: (a) attended detection asking port 5199, failing closed, so
every `allow_unattended=false` secret is refused to attended agents too;
(b) the locked-vault fallback reading `secrets_exec_token.5199`, which that
server never wrote (`tools/with-secret.py:104`, `:120`,
`mc/secrets_exec_stream_client.py:91`), so no agent can use any secret on a
passphrase vault; (c) if another Clayrune does own 5199, the trigger-type
question goes to the wrong install. With `MC_PORT` set to a non-default port
only (a) and (c) apply. The desktop entry point exports `MC_PORT`
(`app.py:475`) so it is unaffected for (b). Read, not measured (needs a
second server). Smallest fix: one `server_port()` helper that reads
`CLAYRUNE_PORT`, then `MC_PORT`, then 5199, used by both; build the
trigger-type URL from it. `tests/test_secrets_store.py` monkeypatches
`_lookup_trigger_type`, so it cannot see the port.

**P5 — `mc/secrets_store.py:2113-2136`, `:1019-1023` — L/E — low.
The redaction table keeps every dispensed plaintext for the life of the process, lock or no lock.**
`_dispensed` maps plaintext value → name and is only pruned on rotate/delete.
`_do_relock` clears `_unlocked_key` and nothing else, so after an idle lock
or "Lock now" the server still holds, in clear, every value it handed out
since boot. `docs/SECRETS.md` "Residual risk" lists what survives a lock and
does not list this. `redact()` also sorts the whole table on every call
(`:2132`). Smallest fix: say so in the doc, or keep a keyed digest plus
length per value for the stream redactor and drop the plaintext on relock.
No test covers the table across a relock.

**P6 — `mc/secrets_store.py:1495-1500` vs `:1537`, `:1545` — M — low.
A wrong old passphrase on change is not audited; a wrong passphrase on unlock is.**
Both unwrap the same leg. Guessing through `change_passphrase` leaves no
`vault_unlock_denied` line. Whether the route rate-limits is in 1b. Smallest
fix: the same `_audit('vault_unlock_denied', …)` in both `except` arms.

**P7 — `mc/secrets_store.py:1344-1346` — M — low.
A keyring read failure is cached as "no legacy key copy".**
`_refresh_legacy_keyring_cache` swallows any keyring exception without a log
line and stores `False`, so `legacy_key_copies_present()` then reports the
legacy copies retired when the truth is unknown. Twenty lines up
(`:1322-1326`) the same module chooses to leave the cache alone in that
case. Project policy asks for a log on this kind of failure. Smallest fix:
log, and leave `_legacy_keyring_entry_cached` unchanged on exception.

**P8 — `mc/secrets_store.py:1704-1707`, `:1715-1724` — L — low.
The ACL verify reads `icacls` output as UTF-8 and looks for English text.**
`icacls` prints in the console code page and prints account names, not SIDs.
The check passes only if the decoded text contains the account string and
either `s-1-5-18` or `system`. An account name with a non-ASCII character
decodes to a replacement character and no longer matches; a locale that
prints SYSTEM under another spelling fails the second test. Both fail
closed, so the result is "cannot set or change a vault passphrase on that
box" with an ACL error, not an exposure. The check also proves the two
grants are present, not that no other explicit ACE is. Read, not measured
(needs such an account). Smallest fix: verify with `icacls /save` (SDDL,
SIDs only) or the Win32 `GetNamedSecurityInfo` the module already has the
ctypes plumbing for.

**P9 — `mc/secrets_store.py:2067`, `:2088` — E — low.
The audit log is never rotated and `audit_tail` reads all of it for the last 100 lines.**
Every read, denial and exec session appends a line; nothing trims. Smallest
fix: read backwards from the end in blocks, or cap the file.

Sound in this file: the mint-only-when-empty rule and the trial decrypt
