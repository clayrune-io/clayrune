### F1 · HIGH — the backup routes' attended-only gate is a header that nothing sends
**Path.** Any agent session — every dispatched agent runs `--dangerously-skip-permissions` (`mc/agent_runtime.py:1080`) and the steward fence explicitly allows mutating `curl` to localhost (`steward/fence.py:188-189`, "steward's own API calls") — can POST to the four routes above. `_is_unattended()` reads `request.headers.get('X-Clayrune-Trigger-Type')`. That header string occurs **once in the repository** (`backup_routes.py:238`); no dispatcher, runtime, or client sets it. The function therefore returns `False` for every request, and each "refused for this trigger type" branch is dead code.

Even if a caller did send the header, the allowlist `('steward','scheduled','unattended')` does not contain the values MC actually records: the scheduler dispatches with `trigger_type='schedule'` (`mc/blueprints/scheduler_routes.py:684,1260`), hivemind uses `hivemind_worker`/`hivemind_orchestrator` (`hivemind_routes.py:972,1045,1285`).

**Concrete trigger.** From a `[Steward cycle]` session:
```
curl -s -X POST localhost:5199/api/backup/export-project/mission_control \
  -H 'Content-Type: application/json' -d '{"vault":true,"vault_passphrase":"x"}'
```
`_resolve_vault_choice(vault=True, 'x', unattended=False)` (`mc/backup.py:1211-1230`) returns `'included'`; `export_all_for_backup()` (`mc/secrets_store.py:847-884`) calls `_open()` on **every project-scoped secret regardless of `allow_unattended`**, seals the JSON under the caller-chosen passphrase (scrypt + AES-GCM, `:880-884`) and writes it to `secrets/vault.enc` in an archive whose path is returned in the response. The caller knows the passphrase, so this is a plaintext-equivalent dump of that project's vault, audited as a single `export` row rather than one `read` per secret, with `allow_unattended=False` never consulted.

Same gate, the write direction: `POST /api/backup/import {"path":…,"apply":true,"vault_passphrase":"x"}` → `import_project(..., unattended=False)` is passed **literally** (`backup_routes.py:465`), so `import_all_from_backup` (`mc/backup.py:1611-1614`) writes entries into the vault through `_import_entry_raw` (`secrets_store.py:895-923`). `on_collision` defaults to `'skip'`, so existing names are not overwritten, but new secrets can be planted by an agent — an agent-facing vault write path, which CLAUDE.md rule 3 says does not exist. `POST /api/backup/rollback/<pid>/<snap>` and `/api/backup/restore` likewise run for any caller.

**Scope limit, stated honestly.** Per-project export applies `scope_filter=project_id` (`secrets_store.py:862`), so **global-scope secrets are not exported** by this path; full `create_backup` reports the vault `not_available` (`backup.py:662,892-896`). Blast radius is "every secret scoped to the named project", not the whole vault.

**Why the tests did not catch it.** `tests/test_backup_phase2.py:101-107` and `test_backup_phase3.py:311-319` call the library with `unattended=True` directly. No test exercises the route's detection; nothing in `tests/` references `_is_unattended` or the header (grep). Same shape as the two guards that shipped broken earlier today: the guard is tested for its behaviour when told it is unattended, never for whether it can tell.

### F2 · HIGH — scheduled runs are fed unattended-origin explorations (learning rail #2)
`mc/blueprints/agent_routes.py:2816-2820` computes the read-floor consumer flag with the **text-only** detector B: `consumer_unattended=_distiller.is_unattended_task(task)`. It is called from `_dispatch_agent_internal` at `:5218`, where `trigger_type` is a parameter of the enclosing function (`:5584-5589`) but is not passed. A scheduled run's task text is the schedule's own text; the only prefix ever added is `[Scheduled run · <ts>]` on *continued* fires (`scheduler_routes.py:913-920`), which matches neither marker.

**Concrete trigger.** Schedule task `"Nightly competitor pass"`, `trigger_type='schedule'`: B returns `False` → `exploration_read_floor(..., consumer_unattended=False)` (`mc/distiller.py:2220-2242`) does not filter `origin: unattended` artifacts → they enter this run's prompt. When the run ends, `mc/memory.py:2289` stamps its own output `unattended` via C (correct). Net: unattended output → unattended input, with no human on either side — the exact circuit `_UNATTENDED_LOOP_RULE` exists to break. The steward path is unaffected (`scheduler_routes.py:523` hard-codes `True`), so the rail holds for stewards and breaks for every other scheduled job.

### F3 · HIGH — the vault's "attended-only" policy is one PATCH away for any agent
`PATCH /api/secrets/<name>` (`mc/blueprints/secrets_routes.py:86-119`) accepts `allow_unattended` from the body with no caller check; `POST /api/secrets` (`:61-83`) and `DELETE` (`:122-130`) likewise. CLAUDE.md states "Agents use credentials; only humans create them. There is no agent-facing write path." `set_secret`'s docstring repeats it (`secrets_store.py:471-472`). The route is the write path, it is on the same unauthenticated localhost surface every agent uses, and the steward fence allows it (`fence.py:188`).

**Concrete trigger**, steward cycle: `curl -X PATCH localhost:5199/api/secrets/gmail.app -d '{"allow_unattended":true}'` then `python tools/with-secret.py --env P=gmail.app -- …`. `detect_unattended_context()` correctly says unattended; `get_secret_value` (`secrets_store.py:678`) reads the flag the agent just flipped. The `allow_unattended` policy backstop is therefore advisory for any agent that reads the API reference.

### F4 · MEDIUM — `/api/session/trigger-type` and the Distiller disagree on the empty case
`agent_routes.py:3828,3836` return `'manual'` when the recorded `trigger_type` is falsy; `distiller.py:1575-1589` treats the same state as unattended, and `tests/test_unattended_allowlist.py:36-39` documents that backfilled rows lose `trigger_type`. So the secrets detector is fail-closed for an *unknown* session and fail-open for a *known-but-unstamped* one. I did not find a live writer that persists a session with an empty `trigger_type` (`:4389`, `:4642`, `:7734` all default `'manual'` at write time), so this is a latent inconsistency rather than a demonstrated leak; the one check that settles it is whether any `*_agent_log.json` row on disk has `trigger_type` in `('', None)`.

**Check done (this box, 2026-09-10):** 745 of 2,295 agent-log rows have an empty `trigger_type`. None of them carries a `[Steward cycle]` or `[Scheduled run` prefix or a `trigger_id`, so every one is a manual chat the backfill could not stamp, and the `'manual'` default is correct for all of them today. Latent, not live. **Downgraded to LOW.**

## 1. Guards that do not guard

### F5 · HIGH — every "human-only" policy that is implemented as a localhost route is agent-callable
The threat model in CLAUDE.md is consistent: agents *use*, humans *decide*. Three decisions are enforced only by "the UI is what calls this route". Every dispatched agent shares the same unauthenticated localhost surface (`/api/session/trigger-type` docstring, `agent_routes.py:3820-3821`: "No auth (matches this project's existing localhost-trust posture)"), and the steward fence's Bash classifier explicitly passes mutating HTTP to `_LOCAL_HOSTS` (`steward/fence.py:36`, `:188-189`). So the decision is available to the very process it is meant to exclude.

| Route | Policy it implements | What an unattended agent gets |
|---|---|---|
| `PATCH/POST/DELETE /api/secrets[/<name>]` (`secrets_routes.py:61-130`) | "Agents use credentials; only humans create them. There is no agent-facing write path." (CLAUDE.md vault rule 3) | Flip `allow_unattended`, plant a secret, delete one. See F3. |
| `POST /api/distiller/promote` (`distiller_routes.py:109-178`) | "promotion is human-only … the steward's PreToolUse fence blocks all writes under `.claude/`, so it cannot self-install a skill" (CLAUDE.md, learning rails) | `write_skill(scope='global')` (`:170-175`) installs a `_proposed/` artifact into `~/.claude/skills/`. The fence blocks the `Write` tool on that path (`fence.py:244-246`) and allows the `curl` that does the same thing. An artifact whose evidence was the steward's own output becomes a skill loaded into its next cycle — the "long way round" `scheduler_routes.py:477-481` says needs a human is one POST. |
| `PUT /api/config` (`settings_routes.py:212-258`) | operator-owned knobs | Any key in `_CONFIG_EDITABLE_KEYS`, including `exploration_readback_enabled`, `agent_permission_mode`, `scheduler_paused`, `port`. (`shared_rules_path` is also editable but is only read at `wire()` time, `server.py:79` → `agent_routes.py:180`, so it takes effect only after a restart, which is human-gated.) |
| `POST /api/backup/{restore,import,rollback,export-project}` | "attended-only" | See F1. |

**Concrete trigger** (steward cycle, all four pass the fence): `curl -s -X POST localhost:5199/api/distiller/promote -H 'Content-Type: application/json' -d '{"directory":"<proposal dir>","scope":"global"}'`.

This is one finding, not four: the fix is a single property (a request-origin signal that the UI has and an agent process cannot forge — e.g. the same server-side `trigger_type` lookup `with-secret.py` already uses, keyed on `CLAUDE_CODE_SESSION_ID`, or a browser-only token), applied to the routes that implement a human decision. Until then, the rules above are documentation of intent, not controls.

### F6 · MEDIUM — the steward fence's egress and restart blocks are Bash-string checks that an interpreter walks around

No pattern matches: the string contains no `http`, no `curl`, no `gh`, no `git push`. Same shape reaches `/api/system/restart` (blocked as a literal at `:60` only) and the browser read path (`:175`, blocked only when the URL is on the command line). The fence's own docstring names this — "a broken fence must never wedge the agent" — and `docs/UNTRUSTED_INPUT_SURFACE.md` §"What cannot be defended" concedes text-level controls do not bound a tooled session. Recorded so nobody reads "egress restriction: PARTIAL for steward" as more than it is: it stops the accidental shape, not a deliberate one.

## 2. Incognito must leave no trace — direct disk readers

Incognito is a per-request flag in **any** project: `agent_routes.py:6109` and `:6239-6243` take `incognito` from the body, and the UI sends it per project (`static/js/conversation.js:4385`). An incognito session in a normal project runs in that project's own tree (`_maybe_isolate_worktree` returns the shared path for incognito, `agent_routes.py:861-862`), so its `.jsonl` lands in the same `~/.claude/projects/<encoded>/` directory as every other chat, indistinguishable on disk. The live path honours the promise (`agent_routes.py:4526-4530`: no agent_log row, no memory append, no condense) and its own comment says the transcript "is outside MC's control". The readers below then bring it back in. Every exclusion that exists is by **project id** (`_incognito` pseudo-project) or by a **live session dict**; no direct disk reader except `mc/desk_voice_seed.py:221,247-250` resolves the boundary before opening files.

### F7 · HIGH — the incognito transcript is re-ingested at the next server start and ends up in MEMORY.md, the Distiller, and every later agent's prompt
Chain, each link verified:
1. **Backfill** `server.py:999-1040` `_backfill_agent_log_from_transcripts`: for every transcript whose csid is not already in the log (`:1004-1010`) — which an incognito session's never is, by design — it **writes a synthesized agent_log row** carrying `task=first_user[:300]` and `summary=last_user[:1000]` (`:1019-1022`). The only exclusion is the `_incognito` project (`:1063`).
2. **Scribe reconcile** `server.py:1166-1173` builds `sess = {…, 'incognito': False, 'housekeeping': False}` — a **literal** — for every un-scribed row and calls `_write_session_memory` (`:1175`), which appends to MEMORY.md and dispatches the Distiller (`mc/memory.py:2289-2299`). The Distiller's own entry gate re-checks with the same literal, `mc/distiller.py:828-830`, so `_distiller_should_proceed`'s incognito test can never fire from that path.
3. **Prompt context** `agent_routes.py:2868` `_recent_claude_transcripts(project_path, limit=5)` → `mc/memory.py:210` → `list_sessions` with no filter → the "Recent conversations" block of **every subsequent agent's system prompt** in that project (last user message + `claude -r <id>`). The sibling blocks at `:2812` etc. guard with `not incognito`, meaning the *recipient* is not incognito — nothing checks whether the *listed* chats were.
4. **Cold search index** `mc/memory_fts.py:139` indexes every transcript in the project dir and `:207-228` indexes agent_log `task`/`summary` (now including the synthesized row); `server.py:1260` skips only the `_incognito` project. Served to `/memory/search` and injected into live turns by `mc/memory_turn.py:296`.
5. **Search** `/api/search/global` (`agent_routes.py:8474-8480`) iterates every project with a `project_path` — the `_incognito` pseudo-project has one (`:337`) — so even the dedicated incognito workspace is full-text searchable from the global search box. `/transcript/<csid>` (`:7891`) resolves any csid in the project.

**Concrete trigger.** Open project X, toggle Incognito, chat once, restart the server. The first user line of that chat is now in `data/projects/X_agent_log.json`, and after the next reconcile pass, a Scribe summary of it is in X's MEMORY.md and its transcript is a Distiller input. Blast radius is the operator's own machine (and their backups: `mc/backup.py:464` and `:1201` rglob every `.jsonl` with no exclusion), not a stranger's — this is a broken promise to the user, not an outward leak.

**Lower-value readers, same class** (no exclusion, UI or telemetry only): `mc/blueprints/topics_routes.py:104-107` (Topics digest prompt), `mc/skills.py:1255-1290` (skill-usage stats walk every project dir), `mc/agent_runtime.py:1546,1635` (Documents / subagent panes), `beacon/briefer.py:65-68` (reads MEMORY.md tail — inherits whatever step 2 put there).

**Readers that do apply the check** (verified): `mc/desk_voice_seed.py:221,247-250`; `mc/memory.py:2906` (Scribe live path), `:2380` (checkpoint); `agent_routes.py:4529`, `:4592`; `scheduler_routes.py:877` (live sessions only).
